# Job Boards

The common job-listing vocabulary -- job postings as they are syndicated and searched, the employers posting them, and the salaries attached -- distilled from the APIs that already exist. Part of [Schema Commons](https://github.com/api-commons/schema-commons),
published by the [API Commons](https://apicommons.org).

Built from the providers tagged Job, Jobs, Job Boards, Job Search, Careers, Employment, Labor Market in [APIs.io](https://apis.io) that
publish their own OpenAPI. Only harvested contracts count -- nothing API Evangelist
generated. Every number below is a count of providers.

## What the market already agrees on

<!-- commons:summary -->
| Concept | Expose it | Readable schema | Core properties (share) | Collection named |
| --- | ---: | ---: | --- | --- |
| job_posting | 23 | 19 | id 74%, name 74%, description 53%, employment_type 53% | jobs 22, job 2, vacancies 1 |

Cohort: 33 providers with harvested OpenAPI, 23 crosswalks. Of the providers exposing a job_posting: 56% create, 91% list, 78% fetch, 44% update, 44% delete. Generated 2026-11-11 by build.py.
<!-- /commons:summary -->

Shares are of the providers with a readable resource schema for that concept. The
extended tier and the long tail of every concept are in [profile.yml](profile.yml).

## What the measurement shows

- Job postings agree on id, name, description and employment_type; company and location reach 47%, and the salary range falls below 30%.

## Artifacts

- [openapi.yml](openapi.yml) -- OpenAPI 3.1 of the shared operations. No one serves it; it
  is the shape to map to. Lints clean against the
  [naming ruleset](https://github.com/api-commons/schema-commons/blob/main/ruleset/schema-commons-naming.yaml).
- [schema/](schema) -- JSON Schema 2020-12 per concept; each property carries
  `x-commons-tier`, `x-commons-share`, `x-commons-providers` and the spellings seen.
- [crosswalk/](crosswalk) -- one per provider, common name -> their name, with the harvested
  spec and operations each mapping was read from.
- [adopters.yml](adopters.yml) -- who exposes which concept, linked to their APIs.io page.
- [concepts.yml](concepts.yml) -- the only hand-written input: concepts, path segments and
  their qualifiers, aliases, reviewed exclusions, merged duplicates, and the decisions below.
- [census/](census) -- the cohort and the raw census the profile is built from.

## Decisions

These are calls, not measurements, recorded so they can be revisited as the method matures.

- The concept is job_posting, because recruiting holds job as the requisition inside an applicant tracking system; this is the posting as boards syndicate and search it. schema.org JobPosting is the reference shape, and its names are preferred where the census ties.
